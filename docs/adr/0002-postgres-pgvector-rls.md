# ADR-0002: PostgreSQL 16 + pgvector + Row-Level Security

- **الحالة:** مقبول
- **التاريخ:** 2026-11-14
- **المرحلة:** 1

## السياق

المنصة تخزن بيانات بحثية خاصة لكل فضاء (workspace)، وتحتاج بحثاً نصياً بالعربية وبحثاً بالمتجهات للـRAG. القاعدة الهندسية 8 تفرض العزل على مستوى قاعدة البيانات، لا على مستوى الكود وحده.

## القرار

### 1. قاعدة واحدة لكل شيء

PostgreSQL 16 مع امتداد `pgvector`: البيانات العلائقية، والبحث النصي، والمتجهات في قاعدة واحدة تخضع لسياسات العزل نفسها. ORM: Drizzle.

### 2. العزل (دفاع مزدوج)

- كل جدول بحثي يحمل `workspace_id NOT NULL`، وعليه سياسة RLS:
  `workspace_id = nullif(current_setting('app.workspace_id', true), '')::uuid`.
  حين لا يكون هناك فضاء مربوط تصبح القيمة `NULL` فلا يظهر أي صف (**fail closed**) بدل رمي خطأ.
- `FORCE ROW LEVEL SECURITY` على كل الجداول المحمية، فتسري السياسات على مالك الجدول أيضاً.
- التطبيق يتصل بدور `bahith_app`: بلا `SUPERUSER` وبلا `BYPASSRLS` ولا يملك أي جدول. الهجرات تعمل بدور المالك/المدير عبر `DATABASE_ADMIN_URL` فقط.
- `withWorkspace(id, fn)` تفتح معاملة وتضبط `app.workspace_id` بنطاق المعاملة (`set_config(..., true)`، وهو المكافئ القابل للمعاملات المُهيأة لـ`SET LOCAL`)، فلا يتسرب الربط إلى الاتصال التالي في الـpool. المعرّف يُتحقق أنه UUID قبل أي استعلام.
- **مفاتيح أجنبية مركّبة:** فحص المفاتيح الأجنبية يتجاوز RLS، فكل علاقة بين جدولين بحثيين هي `(workspace_id, x_id) → (workspace_id, id)`. بهذا يستحيل ربط صف بأبٍ في فضاء آخر حتى لو خُمّن معرّفه.
- **صلاحيات دنيا:** `audit_log` إلحاق فقط (INSERT/SELECT)، `document_versions` بلا UPDATE، `plans` قراءة فقط، وحذف `workspaces` غير متاح لدور التطبيق.
- طبقة الخدمة تتحقق من العضوية والدور أيضاً (من المرحلة 2)؛ RLS هي شبكة الأمان حين يخطئ الكود.

### 3. الجداول غير البحثية

- `users` و`plans` عامّان (بلا `workspace_id`).
- `workspaces` و`memberships` لهما سياسات خاصة: يُريان داخل الفضاء المربوط، أو للمستخدم المربوط (`app.user_id` عبر `withUser`) حتى يستطيع سرد فضاءاته قبل اختيار أحدها.

### 4. البحث النصي بالعربية

- `chunks.tsv` عمود مولَّد: `to_tsvector('simple', app.normalize_arabic(content))` مع فهرس GIN.
- `app.normalize_arabic` (دالة SQL `IMMUTABLE`): تحذف التشكيل والتطويل، وتوحّد صور الألف (أ إ آ ٱ ← ا) وحوامل الهمزة (ؤ ← و، ئ ← ي)، و(ى ← ي) و(ة ← ه)، والحروف الفارسية (ی ک)، والأرقام الهندية والفارسية.
- الاستعلام يمر بالتطبيع نفسه (`arabicTsQuery`). إعداد `simple` بلا تجذير: قرار التجذير يُؤجَّل إلى المرحلة 3 ويُحسم بقياس على المجموعة الذهبية.

### 5. المتجهات

- `chunks.embedding vector(1024)` مع فهرس HNSW (`vector_cosine_ops`)، وعمود `embedding_model` إلزامي مع كل تضمين.
- **1024 بُعداً** لأنه القاسم المشترك لنماذج التضمين متعددة اللغات الجيدة في العربية، وأقل من حد HNSW (2000). تغيير البُعد لاحقاً يتطلب هجرة وإعادة تضمين.

### 6. الهجرات

- `drizzle-kit generate` يولّد SQL الصعود من المخطط. Drizzle لا يولّد هجرات تراجع، فلكل هجرة ملف `migrations/down/<tag>.sql` مكتوب يدوياً.
- مشغّل الهجرات (`packages/db/src/migrator.ts`) ينفّذ كل هجرة في معاملة، ويرفض التشغيل إذا عُدّلت هجرة مطبَّقة (checksum) أو إذا كانت القاعدة أحدث من الكود، ويرفض أي قاعدة غير محلية دون `--allow-remote`.
- كلمة مرور دور التطبيق لا تُكتب في أي هجرة؛ تُضبط بعد الهجرة من متغيرات البيئة.

## العواقب

- **إيجابية:** العزل مُثبت باختبار آلي على كل جدول؛ نقطة نسخ احتياطي واحدة؛ لا مزامنة بين أنظمة.
- **سلبية:** كل استعلام بحثي يجب أن يمر عبر `withWorkspace` (معاملة لكل عملية)؛ سياسات RLS تضيف شرطاً لكل استعلام؛ HNSW يستهلك ذاكرة ويحتاج ضبطاً عند كبر البيانات.
- **ديون معروفة:** `users` بلا RLS في المرحلة 1 (جدول هوية يحتاجه تسجيل الدخول قبل وجود سياق)، ويُحسم مع جداول المصادقة في المرحلة 2 (ADR-0004).
- **حارس آلي:** اختبار يفشل إذا أُضيف جدول فيه `workspace_id` بلا RLS مفعّل ومفروض، أو مفتاح أجنبي بين جدولين بحثيين لا يتضمن `workspace_id`.
