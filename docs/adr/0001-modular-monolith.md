# ADR-0001: مونوليث معياري داخل Monorepo

- **الحالة:** مقبول
- **التاريخ:** 2026-11-14
- **المرحلة:** 1

## السياق

«باحث» منتج MVP بفريق صغير. يحتاج واجهة ويب وAPI، ومعالجة مستندات ثقيلة (PDF/DOCX، تقطيع، تضمين)، وقاعدة بيانات واحدة بعزل صارم بين الفضاءات. المطلوب بناء تدريجي على سبع مراحل مع إبقاء كل مرحلة قابلة للمراجعة والاختبار.

## القرار

1. **مستودع واحد** (pnpm workspaces + Turborepo) بالهيكل:
   - `apps/web` — تطبيق Next.js واحد يضم الواجهة والـAPI (Route Handlers). هذا هو «المونوليث».
   - `apps/worker` — عامل Python واحد لمعالجة المستندات (ADR-0003). ليس خدمة تُستدعى بـHTTP؛ يستهلك من طابور فقط.
   - `packages/*` — وحدات داخلية بحدود واضحة: `db` و`ai` و`citations` و`ui` و`config`.
2. **قاعدة بيانات واحدة** (ADR-0002) هي مصدر الحقيقة الوحيد. لا خدمة تملك بيانات خاصة بها.
3. **الحزم الداخلية تُستهلك كمصدر TypeScript مباشرة** (حقل `exports` يشير إلى `src`) بلا خطوة بناء؛ Next.js يترجمها عبر `transpilePackages`، والسكربتات تعمل بـ`tsx`.
4. **اتجاه الاعتماد واحد:** `apps → packages`، و`packages` لا تعتمد على `apps`. الوصول إلى البيانات البحثية يمر حصراً عبر `@bahith/db` و`withWorkspace`.

## البدائل

| البديل                             | سبب الرفض                                                                                                     |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| خدمات مصغّرة (API مستقل، خدمة RAG…) | تكلفة تشغيل ونشر ومراقبة لا يبررها حجم MVP، وتعقّد العزل (كل خدمة تحتاج تطبيق RLS بنفسها).                     |
| API مستقل (NestJS/Fastify) + واجهة | عمليتا نشر وطبقة عقود إضافية دون حاجة حالية؛ Route Handlers تكفي، والفصل لاحقاً ممكن لأن المنطق في `packages`. |
| مستودعات متعددة                    | تغييرات المخطط تمس الويب والعامل معاً؛ المستودع الواحد يبقيها في commit واحد وCI واحد.                         |

## العواقب

- **إيجابية:** نشر بسيط (تطبيق + عامل)، تغييرات ذرّية عبر الطبقات، CI واحد، وحدود معيارية تسمح بفصل خدمة لاحقاً إن لزم.
- **سلبية:** تطبيق الويب يحمل الواجهة والـAPI معاً فيتوسعان معاً؛ المهام الطويلة يجب ألا تُنفَّذ داخل طلب HTTP بل تُرسل إلى الطابور.
- **التزام:** أي منطق أعمال يُكتب في `packages/*` لا داخل Route Handlers، حتى يبقى قابلاً للاختبار والنقل.
