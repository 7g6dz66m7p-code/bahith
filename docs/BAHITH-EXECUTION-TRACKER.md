## 5. القرارات المعمارية في هذه الجلسة

- **الكتابة إلى قاعدة البيانات من TypeScript فقط:** عامل Python لا يلمس قاعدة البيانات؛ يكتب manifest إلى S3، وعملية Node تُدخله عبر حد `ingestExtraction` الوحيد، مع إعادة تفويض المستخدم.
- **OCR محلي فقط:** صور الصفحات لا تغادر العامل (حماية الوثائق الخاصة). نص OCR موسوم دائماً ويحتاج مراجعة قبل الاستشهاد.
- **نوع الملف من البايتات:** الامتداد ونوع المتصفح غير موثوقين.
- **إزالة التكرار داخل الفضاء فقط:** لا كشف عبر الفضاءات (منعاً لتسريب وجود ملف لدى مستخدم آخر).
- **صورة MinIO:** `coollabsio/minio` (موروث من المرحلة 1).

## 6. المخاطر

- عميل BullMQ لـPython أقل اكتمالاً من عميل Node. المسار مختبر فعلياً بين اللغتين، لكن يلزم إعادة الاختبار عند الترقية.
- جودة OCR العربي تعتمد على جودة المسح. الثقة تُخزن، لكن لا توجد عتبة رفض تلقائي.
- تقديم PDF بلا `CSP sandbox`، لأن عارض المتصفح يرفض المستندات المعزولة. الأنواع الأخرى معزولة.
- لا تشفير على مستوى التطبيق لملفات S3. الاعتماد على تشفير المزود عند الراحة (R2/S3).

## 7. العوائق الحقيقية

1. **مزود نماذج الذكاء الاصطناعي:** لا مفتاح. يحجب الوكيل البحثي والتحقق بالمعنى والتضمين الدلالي.
2. **Staging/Production:** لا حساب استضافة ولا قاعدة بيانات أو Redis أو S3 مُدارة ولا أسرار نشر.
3. **الدفع:** ممنوع تفعيله دون إعداد وتفويض (الأمر التنفيذي، القسم 10).
4. **Google OAuth وSMTP الإنتاجي:** بيانات غير مقدمة.
5. **مواصفات SANAD المقطوعة:** ذكرها GPT في تقريره، ولم تُستلم تتمتها.

## 8. الخطوة التنفيذية التالية
