# تقرير المرحلة 2 — الهوية والحسابات والواجهة

- **التاريخ:** 2026-11-14
- **الفرع:** `claude/new-session-tv7vfk`
- **خط الأساس المتحقق:** `379cc714a4f63a6f6f549405049ea9eac6270d76`

## الملخص

أُضيفت مصادقة Better Auth فعلية بجلسات في PostgreSQL، وتحقق البريد والاستعادة
وTOTP، وإنشاء فضاء شخصي ذري، وواجهة عربية/إنجليزية فاتحة وداكنة. نجحت اختبارات
التسجيل والمشروع والعزل والأمان من المتصفح مع SMTP وقاعدة بيانات حقيقيين مؤقتين.
هذا إنجاز للمرحلة الثانية، وليس ادعاءً بإكمال المنصة أو المحرك ذي الوحدات الأربع.

## ما تم تنفيذه

- `packages/auth`: Better Auth 1.7.23 ومحوّل Drizzle بمعاملات وUUID، وإعداد صريح
  دون أسرار افتراضية، وSMTP آمن، وتحقق بريد إلزامي واستعادة وإبطال جلسات وTOTP.
- `packages/db/migrations/0004_auth_identity.sql`: خمسة جداول هوية خاصة، وRLS للملف
  الشخصي، ودور `bahith_auth` منفصل بلا صلاحيات بحثية، ودور provisioner ضيق بلا
  تسجيل دخول أو BYPASSRLS ينشئ الفضاء وعضوية owner في معاملة إنشاء المستخدم.
- `apps/web`: التسجيل والدخول وإعادة التحقق والاستعادة وتحدي العامل الثاني
  وإعداد TOTP/رموز الاستعادة وQR محلي. لا تظهر Google إلا عند إعداد المزود، ولا
  تتجاوز OAuth العامل الثاني المحلي للحسابات التي فعّلته.
- لوحة بيانات فعلية للفضاءات والمشاريع، وإنشاء مشروع ودعم `Ctrl/⌘+K` مع تركيز
  لوحة المفاتيح، ورسائل مترجمة، وخطي IBM Plex Sans Arabic وNoto Naskh Arabic محليين.
- `packages/db/src/projects.ts` وواجهات `/api/projects` و`/api/sanad/retrieve`:
  جلسة موثقة من الخادم، ورفض userId الذي يرسله العميل، وفحص العضوية/الدور/المشروع،
  وحد JSON فعلي للطلب وOrigin صريح وأخطاء آمنة. حُفظت عقود SANAD الداخلية القائمة.
- `pnpm bootstrap`: يولد إعدادات الدور الخاص وسر المصادقة المحلي دون طباعة قيم.
  Mailpit محلي بـDocker Compose لاستلام رسائل التطوير دون إرسالها خارجياً.
- E2E جديد يبدأ PostgreSQL/pgvector وSMTP Mailpit وRedis مؤقتة، ثم يبني ويشغّل
  Next في وضع الإنتاج. لا يعتمد على حسابات أو cookies مصطنعة أو قاعدة مطور قائمة.
- GitHub Actions يحتفظ بأدلة المتصفح، بما فيها لقطات العربية/الإنجليزية، سبعة أيام.

## دليل المسار الكامل

التسجيل عبر الواجهة ← API Better Auth ← PostgreSQL والدور الخاص ← رسالة SMTP
حقيقية إلى Mailpit ← رابط التحقق ← دخول وكوكي جلسة ← الفضاء الشخصي ← إنشاء مشروع
← إعادة العرض. أُثبت كذلك:

- رفض الوصول المجهول وحقن هوية في body والوصول لمشروع مستخدم آخر عبر HTTP.
- إبطال الجلسات عند الاستعادة والخروج، وتفعيل وتأكيد TOTP ثم طلبه عند الدخول.
- تطبيق 429 فعلياً من محدد المعدل المشترك في قاعدة البيانات.
- استقلال أسرار الهوية عن دور البحث، وذرية الفضاء، واستعادة سياق الاتصال، وصعود
  الهجرة وتراجعها دون تعطيل FORCE RLS.
- 24 فحص axe على dashboard/sign-in في ar/en وعلى 360 و768 و1440px، في الوضعين
  الفاتح والداكن: صفر مخالفات serious/critical وصفر تجاوز أفقي في الحالات المفحوصة.
- فحص بصري فعلي للقطات 360px العربية و1440px الإنجليزية؛ حُفظت ثماني لقطات
  dashboard في مخرجات اختبارات المتصفح غير المتتبعة.

تعيد اختبارات المتصفح تصفير صفوف محدد المعدل في **قاعدة اختبارها المؤقتة** بين
الحالات لعزلها، بينما تبقى السياسة مفعلة ويختبرها اختبار 429 مستقلاً. لا ترسل
الاختبارات بريداً خارج Mailpit، ولا تستخدم أسماء أو بيانات بحثية حقيقية.

## الأخطاء المعالجة

- نسخة Better Auth الحديثة تنفّذ `user.create.after` بعد commit؛ استُبدل تفصيل
  hook في ADR-0004 بـtrigger محدود الصلاحيات يضمن الذرية المطلوبة.
- فحص Origin قبل وجود cookie لا يغطيه المسار الافتراضي في كل الحالات؛ أُضيف
  رفض صريح للـOrigin المفقود/المختلف لكل كتابة HTTP، مع إبقاء CSRF مفعلاً.
- تعطل تشغيل المتصفح أولاً لغياب Chromium المطابق؛ نُزّل إلى مجلد عمل مستقل،
  دون تعديل الاختبارات أو استعمال متصفح غير مطابق.
- كشف axe تسمية زر المظهر غير المتضمنة لنص حالته؛ أُصلحت التسمية. وكشف E2E
  ربط select لغة المشروع بملصق يشمل نص الخيارات؛ فُصل label وربط بـhtmlFor.
  ثم نجح الأمر الكامل بـ14 اختباراً دون تخفيف المحددات أو قواعد axe.

## ما لم يكتمل والخطوة التالية

- بقية الرسالة الجديدة انقطعت عند «تعطيل الاختبارات الفاش…»، ولم تُستلم تعريفات
  الوحدتين المتبقيتين أو معايير SANAD الكاملة. المطلوب هو تتمة النص، لا إعادة البدء.
- لم يُجب اختيار مزود/إعداد مفتاح النماذج بعد؛ لا توجد اتصالات OpenAI أو مفاتيح
  جديدة. تستمر الأجزاء المستقلة، ولا تُعرض استجابات أو تضمينات وهمية.
- الرفع إلى S3 وربط العامل بالملفات وإدارة المصادر والمحرر والتصدير والتقييم
  العلمي وإجراءات الإطلاق ما زالت أجزاء لاحقة. اكتمال هذه المرحلة لا يساوي اكتمال المنتج.
- بيانات Google ومزود SMTP الإنتاجي والتجهيز والنشر الفعلي لم تُقدّم؛ لم تمس
  هذه الجلسة قاعدة إنتاج أو تنشر المنصة للإنتاج.
- ما زال تحذير pytest-asyncio القديم حول نطاق fixture؛ ليس فشلاً ولم يُخفَ.

الخطوة التالية المصرح بها: رفع المصادر وتسجيل نسخها وربط الاستخراج بالعامل مع
عزل المشروع، والاستمرار في الأجزاء الحتمية ريثما يصل اختيار النماذج وبقية المواصفات.
