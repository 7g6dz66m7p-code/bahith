## الملخص

نُفّذت نواة داخلية فعلية للاستخراج والحفظ والاسترجاع المعزول ومطابقة الاقتباسات، مع
اختبار المسار كاملاً لملفات PDF وDOCX وTXT حقيقية مولّدة للاختبار. اجتازت 167 اختبار
وحدة و180 اختبار تكامل، وفحوص الأنواع والتنسيق والفحص الساكن. هذا الجزء **ليس المحرك
الكامل**: المواصفات المستلمة تنقطع في بداية SANAD Verify، والمرحلة الثانية غير منفذة.

## الفحص قبل التعديل

فُحص الفرع وسجل آخر 20 commit وحالة العمل، وقُرئت `CLAUDE.md` و`README.md`
و`apps/web/AGENTS.md` وADRs 0001–0005 ووثيقة PRD وتقرير المرحلة الأولى.
لم توجد تعديلات محلية في البداية، ولم توجد نسخة محلية للمستودع قبل الجلب إلى مجلد العمل.

- الفرع المطلوب عند `89b6bc5`؛ `main` عند `55ce983`؛ رأس طلب الدمج 1 عند `d0a3808`.
- المكدس الموجود: pnpm/Turborepo وNext.js/TypeScript، وPostgreSQL/pgvector/Drizzle/RLS،
  وعامل Python/BullMQ. لم يكن هناك استخراج مستندات أو مصادقة جلسات أو API بحث.
- الأدوات المتحققة: Node 24.22.1، pnpm المثبت للمشروع 10.28.0 عبر Corepack،
  Python 3.12.14، uv 0.13.6، Docker 29.9.2 وCompose 2.40.3.
- خط الأساس: 75 اختبار TypeScript و13 اختبار Python ناجحة؛ lint وtypecheck ناجحان.
  تكامل Redis نجح؛ بدء PostgreSQL فشل أولاً بسبب مساحة Docker قبل تشغيل اختبارات القاعدة.

الموافقة على SANAD-X التدريجي في الطلب الحالي تتقدم على ترتيب المراحل الأقدم في
`CLAUDE.md`. حُفظت حالة المرحلة الثانية؛ لم تُنشأ مصادقة بديلة أو مسارات عامة تثق
بمعرّفات مستخدم من الطلب، ولم تتغير ملفات الويب أو تقرير المرحلة الأولى.

## ما تم تنفيذه

- `apps/worker/src/bahith_worker/sanad/`: استخراج PDF بصفحات فعلية، وDOCX بفقرات
  وخلايا جداول، وTXT بترميز UTF-8؛ نصوص عربية وإنجليزية واتجاه RTL/LTR مستقل لكل مقطع.
  SHA-256 للبايتات، وإصدارات المستخرج والتقطيع، ومواضع Unicode أصلية، وتقطيع افتراضي
  600 رمز تقديري وتداخل 15%. الفشل الجزئي صريح؛ لا تخمين لمحتوى صفحة فاشلة.
- أداة محلية `python -m bahith_worker.sanad`: ملف manifest خاص 0600 دون الكتابة فوق
  ملف موجود؛ stdout للتجزئة والأعداد فقط وأخطاء آمنة بلا نصوص أو تشخيص محلل خاص.
- `packages/db/src/sanad/manifest.ts`: حد Zod لعقد Python/TypeScript؛ يرفض النص
  المختلق والمواضع والصفحات غير المتطابقة، ويطابق حدود 20 مليون Unicode code point.
- `ingest.ts`: كتابة ذرية ومتكررة بأمان، وفحص عضوية ودور ومشروع ومصدر وملف وتجزئة،
  وحفظ التشخيص ونسخة المصدر، ورفض استبدال نسخة منشورة أو الكتابة على مقاطع قديمة.
- `access.ts` و`retrieve.ts`: صلاحيات داخل المعاملة وأقفال تمنع تغيير العضوية أثناء
  العملية، مع RLS والتحقق الصريح من المشروع في المسارين اللفظي والدلالي. البحث الهجين
  يقبل متجهات حقيقية مسبقة الحساب من النموذج نفسه فقط؛ لا متجهات افتراضية أو مصطنعة.
  `mode: lexical` معلن عند غياب المتجه. ترتيب RRF حتمي بدرجات لا تدعي صحة علمية.
- `0003_sanad_provenance`: أعمدة إضافية اختيارية للسجلات القديمة، وتثبيت هوية الملف
  ونص المقاطع المنشورة ومجموعة مقاطعها. يسمح حذف ملف غير مستشهد به بتنظيف مقاطعه؛
  تبقى قيود الأدلة القائمة قائمة. هجرة تراجع واختبارات صعود وتراجع فعلية.
- `packages/ai/src/sanad/verify.ts`: مرشحات ادعاءات عربية/إنجليزية حتمية بمراجعة بشرية،
  ومطابقة اقتباس حرفية داخل مقاطع مسموحة فقط. رفض معرّفات مختلقة واقتباسات معدّلة
  وصفحات يرسلها الطلب. `exact_quote_match` يعني وجود النص فقط، ولا يثبت دعمه للادعاء.
- إصلاح سباق في مساعد اختبار BullMQ القديم: إعادة تحميل المهمة بعد رصد حالتها النهائية
  حتى لا تُقرأ نتيجة أو رسالة فشل من لقطة أقدم. لم يُحذف أو يُتخطّ أي اختبار أو تحقق.

## الأوامر المشغّلة ونتائجها الفعلية

أوامر pnpm أدناه شُغّلت عبر `corepack pnpm` لاستعمال النسخة المعتمدة في المستودع.

| الأمر                                                | النتيجة                                                          |
| ---------------------------------------------------- | ---------------------------------------------------------------- |
| `pnpm install --frozen-lockfile`                     | نجح باستخدام 10.28.0؛ لم يتغير قفل Node                          |
| `pnpm test`                                          | 167 ناجحاً: DB 90، AI 21، web 11، citations 2، worker 43؛ صفر فشل |
| `pnpm test:integration`                              | 180 ناجحاً: DB 175، web 3، worker 2؛ صفر فشل                      |
| `pnpm lint`                                          | 7 مهام ناجحة، بما فيها Ruff وفحص تنسيق Python                    |
| `pnpm typecheck`                                     | 5 مهام ناجحة، بما فيها Next typegen                              |
| `pnpm format:check`                                  | جميع الملفات المطابقة منسّقة                                      |
| `pnpm --filter @bahith/db exec drizzle-kit check`    | نجاح                                                             |
| `pnpm --filter @bahith/db exec drizzle-kit generate` | `No schema changes, nothing to migrate`                          |
| `git diff --check`                                   | نجاح                                                             |
| `gitleaks git --redact --no-banner` + خطاف كل commit | لم يجد أسراراً                                                    |

اختبارات Python للوحدة تستبعد اختباري التكامل بالعلامة الموجودة، والتكامل يستبعد
اختبارات الوحدة؛ جميعها شُغّلت في أمرها المخصص، ولا توجد إضافة `skip` لإخفاء فشل.
فُحصت الحالات الثلاث كاملة: بايتات ملف فعلي ← Python CLI ← Zod ← PostgreSQL بدور
التطبيق ← بحث داخل المشروع ← اقتباس بصفحة PDF الأصلية أو `null` لـDOCX/TXT.
تغطي الاختبارات أيضاً متجهات 1024 بُعداً والنموذج المطابق والعزل والأدوار والفشل
الجزئي ومنع تعديل/إضافة/حذف مقاطع النسخة المنشورة والتكرار وتراجع الهجرة.

### أعطال واجهت التنفيذ وكيف عولجت

1. استُدعي pnpm العام 11 أولاً، فرفض أعمار بعض اعتماديات القفل. استُخدمت بعده
   نسخة المشروع المحددة 10.28.0 عبر Corepack؛ لم تُخفّض سياسة أو تُعدّل اعتماديات القفل.
2. استنفد Docker بمشغل `vfs` القرص عند تكرار طبقات PostgreSQL. حُذف مخبأ ومحملات
   هذه المهمة غير المستخدمة فقط، وأُعيد استيراد **ملفات الصورة الرسمية نفسها**
   بطبقة محلية واحدة مع التحقق من SHA-256 للطبقات وحفظ إعدادات التشغيل. لم تتغير
   صورة المشروع في الكود أو الاختبارات. نجح فحص PostgreSQL 16.16 وامتداد `vector`.
   معرّف manifest الرسمي لمنصة amd64:
   `sha256:018b4a92e634c3a5715f613dd43497e3d8028ae051be7ba6fd127bcffb0e7957`.
3. رُصد سباق اختبار الطابور السابق في إعادة التشغيل وعولج بإعادة القراءة، ثم نجح
   الأمر الكامل بـ180 اختباراً. بقي تحذير pytest-asyncio القديم حول نطاق حلقة fixtures؛
   لا يمثل فشلاً، ولم يُخفَ.

## ما لم يكتمل والمخاطر العملية

- استكمال المواصفات بعد «تحديد الادعاءات العلمية داخل النص. - تص» ضروري لتصميم
  بقية Verify والوحدتين الثالثة والرابعة ومعاييرهما دون تخمين.
- مصادقة Better Auth والواجهات والرفع إلى S3 وجدولة الاستخراج عبر BullMQ غير منفذة.
  الخدمات الحالية داخلية وتحتاج سياق مستخدم موثوقاً؛ ليست بوابة مصادقة.
- لا مزود تضمين أو reranker عصبي أو استدعاءات نماذج أو حصص نموذج جديدة. اختيار
  المزود والنماذج وسياسة إقامة البيانات مطلوب قبل إرسال مستندات بحثية إلى جهة خارجية.
- لا استدلال علمي أو كشف تعارضات دلالي أو استنتاجات أو شبكة أدلة ومراجعة بشرية دائمة
  في هذا الجزء. مطابقة الاقتباس لا تثبت صحة المصدر أو تأييده لادعاء.
- لا OCR أو استخراج رؤوس/تذييلات/مربعات نص/جداول متداخلة في DOCX. قد تؤثر ترميزات PDF
  وترتيب القراءة في جودة النص؛ الفشل أو الغياب لا يُملآن بمحتوى مولّد.
- لا تقييم علمي ذهبي؛ `pnpm eval` بقي هيكل المرحلة الأولى غير المنفذ ولم يُشغّل.
  `pnpm test:e2e` لم يُشغّل محلياً لأن الويب لم يتغير؛ فحص GitHub Actions مستقل.
- قيود الصفحات القديمة تسمح بحالات نصف فارغة بسبب SQL NULL؛ يمنع حد الإدخال الجديد
  وVerify هذه الحالات. لم تُرحّل بيانات قديمة لتشديدها في هذه الهجرة.
- تراجع هجرة 0003 يحتفظ بالجداول والنصوص القديمة، لكنه يزيل بيانات SANAD الإضافية
  وحمايات نسخها؛ يلزم إيقاف مستدعي SANAD قبل أي تراجع. لم تمس الجلسة قاعدة إنتاج.
