1. **نسخة Node واحدة** كانت عنق الزجاجة (≈107% CPU = نواة كاملة) → Caddy أمام 3 نسخ web:
   الإنتاجية 22 ← 35–37 تكراراً/ث (+60%)، صفر أخطاء حتى 100 مستخدم.
2. **Postgres ‏93% CPU** رغم أن التنفيذ نفسه قليل: `pg_stat_statements` مع `track_planning` أظهر
   **33.3 ث تخطيط مقابل 10.6 ث تنفيذ** خلال 40 ث تحت 50 مستخدماً.
   - استعلام البحث: مصفوفة مصطلحات البحث (دالة IMMUTABLE) مكتوبة ≈10 مرات داخل الاستعلام، فيطويها المخطِّط
     في كل موضع: ≈10.6 ms تخطيط لكل بحث مقابل ≈1.2 ms تنفيذ.
   - فحوص العضوية والمشروع: تعمل في كل طلب (≈12,700 مرة في 40 ث)، وتخطيطها ضعف تنفيذها.
