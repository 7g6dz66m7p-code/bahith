# Runbook: النسخ الاحتياطي والاستعادة لقاعدة البيانات

> مختبَر آلياً: `packages/db/test/integration/backup.test.ts` (نسخ من خادم Postgres 16 +
> pgvector واستعادة إلى خادم جديد فارغ، مع التحقق). لا يمس هذا الإجراء أي قاعدة إنتاج
> إلا بتفويض مكتوب من صاحب المشروع.

## ما تحويه النسخة (`--dir`)

| الملف           | المحتوى                                                                                            |
| --------------- | -------------------------------------------------------------------------------------------------- |
| `database.dump` | `pg_dump --format=custom`: المخطط والبيانات وسياسات RLS والصلاحيات                                 |
| `roles.sql`     | تعريف أدوار `bahith_*` فقط (من `pg_dumpall --roles-only --no-role-passwords`) — **بلا كلمات مرور** |
| `manifest.json` | الهجرات المطبقة، عدد الصفوف لكل جدول، وSHA-256 لكل ملف                                             |

النسخة تحوي نصوصاً بحثية خاصة: تُخزَّن مشفّرة عند الراحة (حاوية S3/R2 خاصة بتشفير
المزوّد، أو تشفير إضافي بـ`age`/KMS) وبصلاحيات وصول محدودة، ولا تُرسل إلى أي خدمة أخرى.

## النسخ

```bash
DATABASE_ADMIN_URL=postgres://… pnpm db:backup -- --dir=/secure/backups/2026-11-22
```

يتطلب `pg_dump` و`pg_dumpall` بنفس الإصدار الرئيسي للخادم (16) أو أحدث، ودوراً إدارياً
(لقراءة صفوف كل الفضاءات متجاوزاً RLS).

## الاستعادة

1. أنشئ قاعدة بيانات **فارغة** (خادم جديد أو قاعدة جديدة)؛ الأداة ترفض قاعدة غير فارغة.
2. ```bash
   DATABASE_ADMIN_URL=postgres://…/new pnpm db:restore -- --dir=/secure/backups/2026-11-22
   ```
   تتحقق من SHA-256 لكل ملف (ترفض النسخة المعدّلة)، وتعيد إنشاء الأدوار، وتشغّل
   `pg_restore --exit-on-error`، ثم تتحقق من تطابق الهجرات وعدد الصفوف في كل جدول.
3. `pnpm db:migrate` بمتغيرات البيئة الخاصة بالبيئة المستعادة: يطبّق أي هجرة أحدث ويضبط
   كلمات مرور الأدوار (`bahith_app`، `bahith_auth`) من البيئة.
4. وجّه التطبيق إلى القاعدة الجديدة، وشغّل اختبار دخان: تسجيل الدخول وفتح مشروع وبحث سَنَد.

## زمن الاستعادة (هدف المرحلة 6: أقل من ساعتين)

قيس محلياً على قاعدة الاختبار الصغيرة فقط (ثوانٍ). لم يُقَس على حجم إنتاجي لأنه لا توجد
بيئة إنتاج أو Staging بعد؛ يجب قياسه على Staging بحجم بيانات واقعي قبل الإطلاق.

## ما ليس في هذه النسخة

ملفات المصادر في التخزين S3 (`workspaces/…/files/…`) تُنسخ بآلية المزوّد (نسخ الحاوية
أو تفعيل الإصدارات)، ومفاتيحها مسجلة في جدول `files` (`storage_key`, `sha256`) للتحقق بعد
الاستعادة.
