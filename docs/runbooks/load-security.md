# Runbook: اختبار الحمل (k6) والفحص الأمني (ZAP) والمراقبة

> كل ما هنا يُشغَّل على **المسار المحلي للاختبار فقط** (`apps/web/e2e/server.ts`: بناء إنتاجي
> `next build` + `next start` مع Postgres وRedis وMinIO والعمال الحقيقيين). لا يُوجَّه أي
> فحص أو حمل إلى بيئة إنتاج أو طرف ثالث.

## 1. تشغيل المسار

```bash
pnpm --filter @bahith/db exec tsx ../../apps/web/e2e/server.ts
```

ينتظر حتى `Ready` على `http://localhost:3100`.

## 2. اختبار الحمل (k6)

```bash
cd apps/web && pnpm exec tsx load/prepare.ts > /tmp/load-env.json
```

ينشئ باحثاً حقيقياً (تسجيل، تأكيد بريد عبر Mailpit المحلي، دخول)، ومشروعاً، ويرفع مصدراً
تجريبياً تعالجه العمال الحقيقية. ثم (صورة k6 الرسمية من Docker Hub):

```bash
docker run --rm --network host -v "$PWD/load:/load:ro" -e BASE=… -e COOKIE=… -e WORKSPACE_ID=… -e PROJECT_ID=… grafana/k6:0.57.0 run /load/k6-smoke.js
```

السيناريو `load/k6-smoke.js`: ‏50 مستخدماً متزامناً لمدة 60 ثانية، كل تكرار يطلب الصفحة
الرئيسية وصفحة المشروع وقوائم المشاريع والمكتبة والمراجع وبحث سَنَد. العتبات: أخطاء < 1٪،
p95 للصفحات < 1.5 ث، للواجهات < 0.8 ث، للبحث < 1 ث.

### النتائج الفعلية (2026-11-24، حاوية مشتركة 4 vCPU و15 GB، يعمل عليها أيضاً Postgres والعمال واختبارات أخرى)

| الحالة      | الطلبات | الأخطاء | p95 الصفحات | p95 الواجهات | p95 البحث | التكرارات/ث |
| ----------- | ------- | ------- | ----------- | ------------ | --------- | ----------- |
| مستخدم واحد | 1,590   | 0       | 91 ms       | 99 ms        | 102 ms    | 13.2        |
| 50 مستخدماً  | 6,366   | **0**   | 1.83 s ❌   | 3.29 s ❌    | 1.95 s ❌ | 17.5        |

**التفسير:** الطلب الواحد سريع (~65 ms)، لكن الإنتاجية لم ترتفع إلا من 13 إلى 17 تكراراً/ث
تحت 50 مستخدماً: تشبّع في عملية Node واحدة على حاوية مشتركة، وليس خطأً وظيفياً (0 أخطاء).
**لم تُخفَّض العتبات.** يجب إعادة القياس على عتاد Staging (عدة نسخ من التطبيق، مجمع اتصالات
Postgres مستقل) قبل الحكم. معيار «أول رمز p95 < 8 ث عند 50 مستخدماً» يحتاج مزود ذكاء
اصطناعي برصيد، ولم يُقَس.

## 3. الفحص الأمني (ZAP baseline، فحص سلبي)

```bash
docker run --rm --network host -v /tmp/zap:/zap/wrk:rw zaproxy/zap-stable:2.16.1 zap-baseline.py -t http://localhost:3100/ar -m 2 -J zap-report.json -r zap-report.html -I
```

(صورة ghcr.io محجوبة بسياسة الشبكة؛ الصورة نفسها من Docker Hub.)

### الجولة الأولى: 0 FAIL، 48 PASS، 10 WARN — وما فُعل بها

| التحذير                                             | الحكم           | الإجراء                                                                           |
| --------------------------------------------------- | --------------- | --------------------------------------------------------------------------------- |
| غياب CSP، ‏X-Frame-Options، ‏X-Content-Type-Options | حقيقي           | أُضيفت رؤوس أمان لكل المسارات وCSP للصفحات (`next.config.ts`)                      |
| بيانات حساسة في الرابط (email/password في GET)      | حقيقي           | نموذج بلا `method` يُرسَل GET قبل تحميل JavaScript؛ كل النماذج الآن `method="post"` |
| «under construction» في الصفحة الرئيسية             | حقيقي (نص قديم) | استُبدل بنص صحيح عن حالة ما قبل الإطلاق                                            |
| ملف تعريف `NEXT_LOCALE` بلا HttpOnly                | مقبول           | تفضيل اللغة فقط، يقرؤه next-intl؛ لا يحوي سراً                                     |
| Content-Type مفقود                                  | حميد            | في ردود إعادة التوجيه 307 فقط                                                     |
| تعليقات مشبوهة                                      | حميد            | كلمات داخل حزم JavaScript مصغّرة للإطار                                            |
| Modern Web App / Authentication Request             | معلوماتي        | —                                                                                 |

### الجولة الثانية بعد الإصلاحات (البناء الجديد): **0 FAIL، 51 PASS، 7 WARN**

اختفت تحذيرات الرؤوس الثلاثة وبيانات الاعتماد في الرابط ورسالة «under construction».
التحذيرات المتبقية: `NEXT_LOCALE` (مقبول)، Content-Type في 307 (حميد)، تعليقات الحزم
(حميد)، `CSP: script-src unsafe-inline` (المقايضة أدناه)، «Absence of Anti-CSRF Tokens»
(النماذج الآن POST؛ لكن كل تغيير يمر عبر `fetch` يفحص ترويسة `Origin` على الخادم
`requireSameOrigin`، مع ملفات تعريف SameSite — لا يوجد إرسال نموذج تقليدي يغيّر حالة)،
ومعلوماتيان.

**مقايضة CSP:** سكربتات Next.js المضمّنة تتطلب `'unsafe-inline'` ما لم تُعرض كل صفحة
بـnonce لكل طلب. السياسة ما زالت تمنع سكربتات الأطراف الثالثة والتضمين في إطارات والإضافات
وأهداف النماذج الخارجية. التحسين التالي: nonce عبر `proxy.ts`.

## 4. المراقبة

- `apps/web/src/instrumentation.ts` (‏`onRequestError`): سطر JSON لكل خطأ خادم يحوي نمط
  المسار والطريقة ونوع الخطأ وdigest فقط — بلا رسالة أو مكدّس أو جسم أو رؤوس (قد تحوي نصاً
  بحثياً أو رموزاً). مختبر في `test/unit/request-error-log.test.ts`.
- عمليات Python وNode للخلفية تكتب أصلاً سجلات JSON بالمعرّفات والرموز فقط.
- Sentry/OpenTelemetry/Langfuse: لم تُربط — تحتاج DSN/نقاط استقبال من صاحب المشروع. السجلات
  الحالية بصيغة JSON جاهزة لأي مُجمِّع سجلات في Staging.
